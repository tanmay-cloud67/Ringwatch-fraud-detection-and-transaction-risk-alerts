API reference & quick guide

Use the local API for repeatable demos; no account, key, external service or database is required.

Open full README

Useful endpoints

  • GET /api/status — active dataset and latest pipeline attempt.
  • GET /api/sample — load deterministic sample data.
  • POST /api/upload — multipart CSV upload under 20 MB.
  • GET /api/features?kind=transactions|accounts — actual paginated feature rows.
  • GET /api/cases?budget=N — ranked cases and coverage.
  • GET /api/config, PUT /api/config — inspect or update detection settings.
  • GET /api/download/sample|processed|rejected — CSV exports.
  • DELETE /api/data — clear the active in-memory dataset.

Three-minute demo

  1. Load the built-in sample or upload the included CSV.
  2. Review row accounting, the six-stage hand-off report, model formula, and feature tables.
  3. Compare graph links and detected rings, then open a ranked case.
  4. Move the review-budget slider and update a case status.
  5. Use Settings to change a threshold and rerun; read the separate assumptions page before interpreting results.

Memory-only: uploaded transactions, case statuses, and pipeline results remain in this server process and are cleared on restart. Clear data removes the current dataset and results; Settings are preserved.

Investigation endpoints

  • GET /api/pipeline — six-stage status, hand-offs, model facts, previews, rings and latest failed attempt.
  • GET /api/graph — directed account nodes, aggregated links, ring IDs and metrics.
  • GET /api/account/{account_id} — account risk reasons and transaction detail.
  • GET /api/case/{id} — case evidence and transaction score breakdown.
  • POST or PUT /api/case/{id}/status — set confirmed, false-positive or escalated status.
  • POST /api/detect — rerun the loaded data with current settings.
  • POST /api/clear — alias for clearing in-memory data; settings remain.
READ BEFORE INTERPRETING SCORES

Assumptions and limitations

RingWatch is an investigator-led synthetic demonstration, not a banking decision system.

IMPORTANT CONTEXT

What these signals do — and do not — mean

  1. 01

    The sample data is synthetic and the injected patterns are intentionally simplified for a short demonstration.

  2. 02

    Thresholds, scores, and rules are illustrative. They are configurable examples, not validated bank thresholds or probability estimates.

  3. 03

    The model has not been validated on real bank data. Isolation Forest scores are relative to the active dataset. A higher score means more unusual in this dataset, not more likely to be fraud.

  4. 04

    The model uses exactly six transaction features. Optional is_fraud labels are excluded from rule/model inputs and used only for synthetic coverage and precision evaluation.

  5. 05

    RingWatch supports human investigators. It does not block, approve, report, or make final decisions about transactions.

  6. 06

    CSV data, results, and case statuses are held in server-process memory. A restart clears them; there is no database or durable upload storage.

Scores prioritize review; they do not confirm fraud.
